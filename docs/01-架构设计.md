> **状态**：`v1.0 已冻结`（2026-10-11 起草；同日吸收外部调研与旧代码审计，并经用户逐项拍板）

## 1. 需求与硬约束

| 编号 | 需求 | 对架构的硬性影响 |
|---|---|---|
| R1 | **完全自主**，无需人工介入 | 必须自带安全兜底（体力/时间/模态/卡死），不能依赖人在旁边按按钮 |
| R2 | **会规划**：不是写死脚本，要能做目标分解、优先级、资源权衡 | 决策层要与执行层解耦；规划必须能"依据当前世界"重新决策 |
| R3 | **会操作**：在真实游戏里完成动作 | 需要一层可靠的游戏内动作原语（走/用工具/交互） |
| R4 | **长程运行**：跨游戏日、跨季节连续游玩 | 需要持久化记忆与世界模型；需要崩溃/卡死恢复 |
| R5 | 分阶段交付：P1 架构 → P2 基本操作 → P3 清障+种田端到端 | 架构要允许"先窄后宽"，能力可插拔 |
| R6 | 开发过程可记录、可持续迭代优化 | 一切决策/动作/状态落盘；文档与代码同源 |

**现实约束（实测）**：《星露谷》实时驱动——游戏内 1 分钟 ≈ 0.7 秒现实时间，一天（6:00→2:00）约 14 分钟现实时间（**待 P2 实测确认**）。这意味着：LLM 不可能逐步决策（一次调用几秒 ≈ 游戏内几分钟），但一天有几十次调用预算是够的；**移动距离就是时间成本**，任何计划都必须算路程。

## 2. 设计原则（8 条，冲突时按序优先）

1. **脑体分离**：LLM 不碰帧。游戏内操作全部由确定性代码在主线程执行。
2. **真值优先**：能从游戏 API 读到的，绝不靠猜（不用截图/OCR 做主要感知）。
3. **契约优先**：每个动作/任务都有 `前置条件 → 执行 → 后置校验`，失败必须带**机器可读原因**。
4. **没有反馈就不算完成**：任何失败都要回流到决策层与记忆层；禁止静默丢弃（旧方案的头号死因）。
5. **进度契约**：任务在给定预算内没有产生可度量的状态改善，必须改变行为（重试→换路→换目标→上报），禁止原地空转。
6. **一次一件事**：任务串行执行；只有安全类事件可以抢占。
7. **默认只做合法操作**：不走内存改写/瞬移等特权路径；特权仅限"运维解卡"，且默认关闭、必须记日志（见决策 4）。
8. **可回放**：决策、动作、世界快照全部落 JSONL，任何一次运行都能离线重放与回归测试。

## 3. 旧方案复盘：我们用证据推翻的四个假设

> 详细代码证据见 `00-开发日志.md` 条目 001 与 `_legacy-audit.md`。

| 旧方案假设 | 实测结果 | 新架构的对策 |
|---|---|---|
| "LLM 输出坐标动作清单，执行器照着做" | 39/39 全 SKIP（`ai_result.json`：`done:0 skipped:39 failed:0`），6 天空转 | **LLM 只输出任务意图**（做什么、在哪片区域、为什么）；坐标与动作序列由技能层按**当下**世界状态计算 |
| "文件轮询 20 秒下发一次计划" | 计划下发即过期（`issued_at` 与 `plan_basis` 错位；`planner.log`：快照过期 1397s） | 改为**结构化 RPC + 世界版本号**，脑的每个决策记录所依据的 `world_seq` |
| "干不了就先放下，看门狗会处理" | `DiscardTask("跨地点退避中")`（`ModEntry.cs:643/1110/1145`）静默吞掉任务，`failed=0` | **失败是一等公民**：不可达/前置不满足必须作为结构化结果返回并写入经验库 |
| "缺什么补什么"（看门狗/黑名单/兜底/瞬移/救援） | 10+ 个旋钮仍在空转 | 用**任务层 + 进度契约 + 升级阶梯**替代全部兜底旋钮 |

**一句话结论**：旧方案不是"有 bug"，而是**开放环**。新架构的中心任务就是把环闭上。

### 3.1 静默空转的完整链条（审计实测，逐环节有行号）

> 全部来自 `_legacy-audit.md` 对源码与运行期产物的实读。运行期事实：`ai_result.json` = `done:0 / skipped:39 / failed:0 / elapsed_seconds:0.6`；`farm_tiles.json` 里 `liveness.world_advancing=true`（**世界没停**，排除了失焦暂停这个常见嫌疑）。

```
玩家在 FarmHouse，39 条动作全指向 Farm
  → 每条任务各自尝试"怎么去农场"
  → 全局退避闸门命中：ModEntry.cs:641-645  DiscardTask("跨地点退避中")
     （退避由 :442-459 点亮：12 秒等待超时 → 全局失败计数 ≥3 → 30 秒退避）
     （关键：重新规划**不重置**这个全局标量 → 退避期内每条任务无条件被丢弃）
  → 39 条在 0.6 秒内"处理完毕"，全部计入 skipped，failed=0
  → 该"处理完毕"被当作正常收尾写进 ai_result.json
  → 规划器（ai_planner.py）认定"上一轮跑完"，立即再规划
  → 每 25~40 秒烧一次 API，农场指纹逐轮完全一致（planner.log:1685/1720/1757）
  → 唯一该救场的看门狗被短路：Diagnostics.cs:192  if (_pending.Count > 0) return true;
     （队列非空 ⇒ IdleIsLegitimate() 恒真 ⇒ 永不判定卡死）
```

**系统在每个环节都"觉得自己正常"——这才是它能静默空转 40 分钟的根本原因。**

### 3.2 五个架构级缺陷（新架构必须逐条对应解决）

| # | 旧缺陷 | 证据 | 新架构的对策 |
|---|---|---|---|
| D1 | **结果没有语义区分**：`AiNoteSkipped` 与 `AiNoteResult` 都递增同一个完成标志（`Ai.cs:540` vs `:565`）⇒"被全量丢弃"与"圆满完成"在协议里无法区分 | 正反馈空转，每 25~40 秒烧一次 API | §5.4 的 **VERIFIED / needs_review / veto 原因码**三态分离 |

## 4. 总体架构

```
┌──────────────────────────── 脑（外部进程，Python） ─────────────────────────────┐
│                                                                                │
│  ⑦ 记忆与知识层   事实库(crops/economy) │ 世界模型(farm蓝图) │ 经验库 │ 日报/轨迹 │
│         ▲                                                              ▲        │
│         │                                                              │        │
│  ⑥ 决策层                                                                       │
│     ├ 快脑（安全守护/中断/故障升级）   ~100ms 级，纯代码                          │
│     ├ 效用层（候选任务打分，无 LLM 也能连续游玩）~1s 级，纯代码                    │
│     └ 慢脑（LLM 情境简报 → 结构化计划）分钟级，DeepSeek API                       │
│         │                                                                      │
│  ⑤ 任务层   Task{kind,params,前/后置,预算,重试}  串行调度 + 进度契约 + 升级阶梯    │
│         │                                                                      │
│  ④ 技能层   move_to / use_tool / plant / harvest / interact / exit_building ... │
│         │                                                      每个技能自校验     │
└─────────┼──────────────────────────────────────────────────────────────────────┘
          │  ③ 通信层：本地 HTTP(RPC) + WebSocket(事件/流)  · 127.0.0.1 + token
          │           每个响应带 world_seq；请求只在主线程执行
┌─────────┼──────────────────────── 体（SMAPI Mod，C#） ──────────────────────────┐
│  ② 动作池/Affordance 层   该格现在能做什么、代价多少、做完变成什么（带前置条件）  │
│  ① 感知层  世界快照：玩家/地点/背包/地块/作物/机器/NPC/时间/天气/UI 模态          │
│            （读游戏对象真值；不截图）                                            │
│  ⓪ 游戏主线程  UpdateTicked 队列排空：绝不在 HTTP 线程碰游戏对象                  │
└────────────────────────────────────────────────────────────────────────────────┘
```

**数据流（一次典型决策）**
```
体 → 事件/快照(带 world_seq)
      → 脑：快脑安全检查 → 效用层挑候选 → （必要时）慢脑出计划
      → 任务层下发单个技能调用
体 → 前置校验 → 执行 → 后置校验 → 结果(ok/unreachable/blocked/timeout/…)
      → 脑：写经验库 + 轨迹 → 决定下一步
```

## 5. 各层契约

### 5.1 感知层（体侧）
- 输出 `WorldState`，字段至少包含：
  - `world_seq`（单调递增，任何世界变化后 +1）
  - `clock`：年/季/日/游戏内时刻/天气/是否节日
  - `player`：地点、tile、朝向、体力/上限、血量、金钱、等级、工具与耐久、背包（含数量与类别）
  - `location`：名称/类型、是否农场/农舍/矿洞、角色数
  - `farm`：地块统计（耕地/作物/成熟/未浇水/枯死/障碍分类计数）、设施与机器状态、动物
  - `ui`：是否存在模态菜单/对话/过场/节日/弹窗（**无人值守的关键字段**）
  - `capabilities`：当前可用的动作类型清单（由动作池决定）
- **快照分层**：`summary`（< 4 KB，给慢脑）/ `full`（全量，给效用层与调试）/ `tiles`（按区域查询，避免 244 KB 全量搬运）。

### 5.2 动作池 / Affordance 层（体侧）
这是旧方案里已经有的正确雏形（`farm_tiles.json`），新架构把它升级为**带前置条件与代价的可用动作**：
```json
{ "id":"A202", "action":"till", "tile":[56,22],
  "pre": { "walkable_reachable": true, "tile_state":"tillable", "tool":"hoe", "stamina_cost":2 },
  "post": { "tile_state":"tilled" },
  "cost": { "ticks": 22, "travel": 3.1, "stamina": 2 },
  "blocked_by": [] }
```
- **脑永远基于 affordance 决策，而不是基于"tile 上有没有草"**——这是杜绝"计划了做不到的事"的根本手段。
- 不可达/前置不满足的动作**可以出现在池里但必须标记原因**（例如 `blocked_by:["unreachable"]`），供慢脑诊断；但不能被派发。

#### 5.2.1 地点拓扑（Location Graph）—— 禁止硬编码坐标

旧方案把"把角色送到工作地点"当成了**每个动作任务的附带步骤**，而不是一个独立可查询、可失败的能力。这是 FarmHouse→Farm 死结的根源（见 §3.2 D2/D3）。

- **节点** = 地点（Farm / FarmHouse / Town / BusStop / Mine / …）；**边** = 门与传送（warp），每条边带：入口 tile、出口 tile、目标地点、落点、通过条件。
- 拓扑由**体侧从游戏真值导出**（真实 `warps`），并提供查询：`GET /v1/path?from_location=&to_location=` → 返回可行路径（含每段入口/落点与预估耗时）**或明确的失败原因**。
- **铁律：禁止硬编码坐标。** 取不到权威坐标时必须**报错**，绝不允许回退到猜测值——旧方案的硬编码 `(64,15)` 泄漏进了模型 prompt，导致模型"基于错误事实做出正确推理"，这类错误比崩溃更难发现。
- 拓扑是**世界模型的一部分**（§5.6），跨日复用，并在每次进入新地点时增量校验。

### 5.3 技能层（体侧执行 + 脑侧编排）
P2 目标技能清单（每个都必须有前置校验与后置校验）：

| 技能 | 后置校验（可判定） |
|---|---|
| `move_to(tile, timeout)` | 玩家坐标 == 目标 且 未卡住 |
| `move_to_location(name)` / `exit_building()` | `Game1.currentLocation.Name` == 目标（**直击旧方案死结**） |
| `use_tool(tool, tile)` | 目标格状态变化（锄地/浇水/砍/敲石/割草） |
| `plant(seed_id, tile)` | 格子出现对应 `HoeDirt.crop` 且背包种子 -1 |
| `harvest(tile)` | 作物消失且背包产物 +1 |
| `pickup_debris(tile)` / `collect_machine(obj)` | 掉落物/机器产出进入背包 |
| `refill_watering_can()` | 水壶水量增加（不等于满） |
| `talk(npc)` / `buy(item,qty)` / `sell(item,qty)` | 对话推进 / 金钱与背包变化 |
| `sleep()` / `dismiss_modal()` | 进入下一天 / 模态消失 |

- 每个技能返回统一结构：`{status: ok|unreachable|blocked|precondition_failed|timeout|ui_modal|aborted, reason, elapsed_ms, state_delta, world_seq}`。
- **候选集约束**：脑只能从体侧给出的候选（affordance）里选技能与目标；**返回值必须属于当前候选集**，超出候选集的请求一律拒绝并返回 veto 原因（`no_candidate`）。
- **时效拒绝**：请求携带 `based_on_seq`，世界已显著变化时体侧直接拒绝并返回 `stale`。**过期决策永不执行**（agent-stardew 与 stardew-together 的 `ExecutionContract.cs` 都是这么做）。
- **🔴 前台约束（实机实测，2026-10-11）**：执行**任何会移动角色**的技能之前，脑必须确保游戏窗口处于前台。
  实测：失焦时 `PathFindController` **不驱动角色**（10/10 失败，角色 6.6 秒内一格未动），**而世界时间照常推进**——这会造成"程序以为在干活、其实角色没动"的假象。回到前台后同样 5/5 成功。
  实现：`brain/agentfarm/winfocus.py`（Windows 焦点 API）→ `agentfarm focus`；`move` 类技能自动先调用。
  **这是部署硬约束：无人值守运行时游戏窗口必须保持前台（已获用户确认接受）。**
- **🔴 不伪造输入**：脑**绝不**发送合成键鼠事件。用户自己点击游戏窗口就触发了一次挥工具（体力 270→266）——杂散输入会变成真实游戏动作，所以自动化只走游戏 API，绝不模拟输入。

### 5.4 任务层（脑侧）
```python
Task = { kind, params,
         precondition, postcondition,      # 可判定谓词
         priority, budget:{max_seconds, max_attempts},
         on_fail: [retry, re_path, substitute, blacklist_hint, escalate] }
```
- **调度**：串行；安全事件可抢占；同一时刻只有 1 个"进行中"任务。
- **进度契约**：`progress = postcondition 度量改善 或 state_delta 非空 或 **世界指纹变化**`。
  > 世界指纹 = 对与任务相关的那部分世界状态取哈希（地块/背包/金钱/作物/位置）。旧方案用"队列空了"当"跑完了"（`Ai.cs:540` vs `:565` 无法区分"全被丢弃"和"圆满完成"），指纹让"真的什么都没变"变得**可判定**。
  规则：**任务结束时若 `done==0` 且世界指纹未变，一律判为失败（或 veto），绝不允许记为完成。**
- **升级阶梯**（连续 N 秒无进度触发）：
  1. 原地重试（含重新面向/换站位）
  2. 重算路径（换出口/换路线）
  3. 换同类目标（就近替代格）
  4. 标记该 tile/区域为"暂时不可达"，写入经验库（带原因与时间戳）
  5. 上报慢脑，请求换任务或重新规划
- 这一层**完全取代**旧的 `Watchdog / Blacklist / FallbackDirectMode / AutoRescue / AllowTeleportFallback / CrossLocationMode` 等旋钮。

**Veto 是一等公民（本架构对旧方案的核心纠正）**
被拒绝/被跳过的任务必须产出**结构化原因码**并回灌候选生成，而不是静默丢弃：

| veto 原因码 | 含义 | 回灌后的行为 |
|---|---|---|
| `no_candidate` | 当前世界没有该动作的合法候选 | 不派发；把该目标从本轮候选中剔除并记录 |
| `precondition_failed` | 缺工具/背包满/种子不足/地形不对 | 生成"补齐前置"的子任务（如先清背包、先买种子） |
| `unreachable` | 寻路无法到达 | 标记区域+时间戳写入经验库；换同类近邻目标 |
| `resource_short` | 体力/时间不足 | 触发快脑兜底（进食/回家睡觉） |
| `stale` | 决策依据的世界已过期 | 立即重新观测并重算，**不重发** |
| `ui_modal` | 被菜单/对话/过场挡住 | 交给模态处理层，稍后重试 |

**回执与账本分离（只信游戏证据）**
> 「购买请求入队时**不会**增加已购数量，只有**原生到货证据**才更新账本与记忆。」——这是长程不漂移的根基。

- 任务只有两种终态：**`VERIFIED`**（后置条件由游戏状态差分证实）与 **`needs_review`**（模型/代码认为做完了，但没有硬证据）。**两者绝不能混为一谈，也不允许用 `needs_review` 冒充完成。**
- 所有资源数字（种子数、金钱、作物数）都必须能回答："这条数字的证据来自哪次原生回执？"

### 5.5 决策层（脑侧，三层）
| 层 | 频率 | 输入 | 输出 | 纯代码? |
|---|---|---|---|---|
| 快脑（安全守护） | 每 tick ~ 100ms | UI 模态、体力、血量、时刻、卡死信号 | 中断/兜底动作（关菜单、吃药、回家、睡觉） | 是 |
| 效用层（候选打分） | ~1s | 候选任务 + 经验库 + 长期目标 | 下一个任务 | 是（**没有 LLM 也能连续游玩**） |
| 慢脑（LLM） | 分钟级 / 事件触发 | **情境简报 ≤ 2 KB** | 结构化计划（1~5 条任务意图 + 理由） | 否 |

- **慢脑触发（事件驱动的摊薄推理，采纳 SPIKE 的做法）**：只在**有意义的边界**唤醒，而不是每步一问——
  1. 新的一天开始 / 每游戏内 30 分钟（常规心跳）
  2. **进度停滞**（任务 N 秒无状态改善）
  3. **重复检测**（同类任务连续失败 / 同一区域反复尝试）
  4. **失败**（veto 或异常终止）
  5. **环境显著变化**（换地点、换季节/天气突变、模态未预期、收到新目标）
  6. 人类指定目标
  稳定区间由效用层与技能层连续推进，**LLM 调用次数 = 边界次数**（这是成本与延迟的关键）。
- **局部覆盖（local override）**：反应式控制器的安全动作（关菜单、脱战、睡觉）可以**抢占**战略计划，战略层事后从新状态重新投影，而不是继续执行旧计划。
- **慢脑输出 schema（严格）**：
```json
{ "goals":[{"id":"greenhouse","why":"长期最高优先级","priority":1}],
  "tasks":[{"kind":"clear_area","params":{"area":[[56,19],[67,26]],"filter":["weed","stone"]},
            "why":"紧邻出口，连片，单位时间收益最高","expect":{"obstacles_removed":">=8"}}],
  "read_fields":["farm.weeds","player.stamina"] }
```
- **校验链**：schema 校验 → 引用的简报字段必须存在（防幻觉）→ 用 affordance 池校验前置可行性 → 任一失败则退回重问 1 次 → 再失败**降级到效用层**继续玩（不能让一次坏计划停摆）。
- **成本控制**：每日调用上限、简报裁剪、相同处境缓存（world 特征哈希）。

#### 实测的慢脑预算（2026-10-11，`deepseek-flash`；详见 `04-配置与密钥.md`）

| 问题规模 | 延迟 | 合计 token | 其中推理 |
|---|---|---|---|
| 极短（"压缩成 4 个字"） | 3.2 s | 545 | 496 |
| **真实规划**（"482 金 / 体力 268 / 农场 443 杂草，今天最优先做什么"） | **41.4 s** | **7123** | **6977** |

三条由此得出的设计约束：

1. **成本几乎全是推理**（>95% 的 completion token 花在思考上）→ 事件触发 + 少调用 + 缓存不是优化项，而是**必需项**。
2. **一次真实规划 = 41 秒现实时间 ≈ 游戏内 58 分钟**，LLM 思考时游戏世界在流逝。
   → 对策：**思考前用游戏菜单暂停时间**（单人模式打开菜单会停表；这是合法游戏操作，不违反 D4 的"不做特权操作"），思考完关菜单再执行。**待 P3 真机验证该行为。**
3. **`max_tokens` 必须 ≥ 8192**。给 2048 时 token 全被思考吃掉、`content` 返回空字符串——只看 `content` 的客户端会把"没想完"误判成"无话可说"。客户端必须把这种情况报成 `truncated`。

### 5.6 记忆与知识层（脑侧，旧方案的最大缺口）
| 库 | 内容 | 用途 |
|---|---|---|
| 事实库 `data/` | 作物经济（复用 `crop_economics.json`）、售价、NPC 喜好、节日日历 | 规划依据 |
| 世界模型 `state/world.json` | 农场蓝图（bed 布局）、已建设施、已知路径/出口图、区域可耕性 | 跨日复用，避免重复探测 |
| 经验库 `memory/experience.jsonl` | `(taskKind, location, area, reason)` 的成功/失败计数、最近失败时间 | **每次慢脑决策必须读到最近失败摘要** |
| 决策日志 `memory/journal.jsonl` | 每次决策的输入摘要、候选、选择、理由、结果 | 复盘与"为什么这么做" |
| 轨迹 `logs/trace-*.jsonl` | 动作级前后状态（含 world_seq） | 离线回放、回归测试、统计 |

- **记忆三分（采纳 stardew-together）**：**事实事件**（原生回执 / 资源变化）｜**计划承诺**（目标、依赖、未完成项）｜**经验规则**（带适用条件的失败规则、日/季摘要）。
  三条铁律：**历史流水不累加成当前库存；计划不算已完成；摘要不能覆盖实时状态。**
- **上下文投影而非追加历史**：每轮按当前决策需求重新"投影"出上下文并设硬预算（慢脑简报 ≤ 2 KB）；**关键约束超出预算时明确报错，不静默裁剪**——静默裁剪会让模型在"缺约束"的情况下做决策，是长程漂移的隐形推手。
- **⚠️ 已知数据缺陷（`crops.json`）**：旧 `crop_economics.json` 的 19 条作物里有 **8 条 `profit_per_day` 与其自述公式矛盾**（偏差 71%~170%，最极端三条算出负数），且**不自恰的全部是 `regrow>0` 的多收作物**——同一字段被用了两种口径。
  → **在真机用 `Crop.RegrowsAfterHarvest()` 重算之前，禁止用 `profit_per_day` 给多收作物排序**（否则会把 Cranberry 排在 Pumpkin 前，而按自述公式关系相反）。
  → 证据与逐条偏差见 `brain/data/crops-consistency-report.json`；原始数值**未改动**。

### 5.7 监督与安全层（脑侧）
- **心跳**：体侧写心跳（含 `world_seq` 与游戏内时刻），脑侧超时 → 判定卡死。
- **无人值守硬条件**：失焦不暂停（`pauseWhenOutOfFocus=false`，旧方案已实测确认游戏会读该选项）。
- **模态处理是一等公民**：任何时刻检测到菜单/对话/过场/节日/升级弹窗/昏倒结算 → 优先交 `dismiss_or_handle_modal()`，而不是等看门狗。
- **兜底顺序**：体力耗尽 → 吃东西/回家睡觉；2:00 → 强制睡觉；血量低 → 脱离战斗；连续失败 → 停止自动化并进入安全态（而不是继续空转）。
- **存档保护**：只用专用测试存档；运行前备份；危险操作白名单。（`SaveBackup` 已装）

### 5.8 可观测与人机接口（P3+）
- `afmon` 面板/CLI：当前任务、最近决策理由、成功率、卡点 TOP N、当日日报。
- 可选 DSH 插件形态接入（见决策 2），用于**观察与人工干预**，不是控制回路的必需件。

| # | 设计 | 落地位置 | 依据 |

| 4 | **YAML 任务套件 + 固定存档 + 步数预算**（直接用 StarDojo 字段名，便于与公开结果同口径对比） | §8 / §9 | StarDojo `farming.yaml`：`object/quantity/tool/save/init_commands/evaluator/difficulty`；难度 ↔ 30/50/150 步上限 |
| 5 | **记忆三分 + 上下文投影 + 硬预算报错** | §5.6 | stardew-together `MemoryArchive.cs` / `DecisionContext.cs` / `ContextBudget.cs` |

**延迟预算参考（说明我们的路线延迟可行）**
- agent-stardew 实测一轮决策 **488 / 566 / 607 / 825 / 4384 ms**（动作粒度粗、无视觉输入）；
- StarDojo 每步 **48.7 s**、ReAct-like **24.5 s**；
- 游戏 1 游戏日 ≈ **14 分钟**现实时间（每 10 游戏分钟 = 7 秒）→ 每步 48.7 s 的路线，一个 150 步任务光推理就 ~2 小时，游戏内时间还在流逝。
→ **结论：必须走"低频 LLM + 高频代码"，且 LLM 调用要按边界摊薄。**

**期望管理（防止自我欺骗）**
学术 benchmark StarDojo-Lite 上最强模型 GPT-4.1 总成功率仅 **12.7%**，中/高难度接近 0。
→ 我们 P3 的目标应聚焦**中等难度、可判定、可复现**的农务任务，并如实报告指标（含 Recovery/Stuck Ratio），不宣称"解决了通用自主游玩"。

**反面警示**
GUI agent 研究（arXiv 2606.14106）发现**盲目增加全图记忆会减少状态级失败，却加重动作级失败**（隐藏操作盲区、grounding error）。
→ 我们的对策是**在动作层做约束（候选 + 前置校验 + veto 回灌）**，而不是"给 LLM 喂更多状态"。

## 6. 通信协议设计（v2 草案）

**为什么换掉文件协议**：文件轮询没有请求-响应语义、没有超时/错误码、没有版本号，导致"计划下发即过期"和"失败静默"。新协议保留文件快照**仅用于离线调试与落盘记录**。

**传输**：Mod 内 `HttpListener` 绑定 `127.0.0.1:<随机端口>`，写 `bridge.json`（端口 + token）供脑发现；事件用 WebSocket 或长轮询。**所有游戏对象访问必须在主线程**：HTTP 线程只把请求塞进 `ConcurrentQueue`，由 `UpdateTicked` 排空执行。

```http
GET  /v1/observe?detail=summary|full          → WorldState + world_seq
GET  /v1/observe/tiles?area=x1,y1,x2,y2       → 区域地块与 affordance
GET  /v1/events?since=<seq>                   → 事件流（DayStarted/LocationChanged/UiModal/Stuck/…）
GET  /v1/path?from=x,y&to=x,y                 → 可达性 + 预估时间（脑排计划前预演）
POST /v1/exec   { "skill":"till", "args":{"tile":[62,20]}, "expect":{...}, "timeout_ms":8000, "based_on_seq":1234 }
     → { "status":"ok", "reason":"", "elapsed_ms":3210, "state_delta":{...}, "world_seq":1260 }
POST /v1/mode   { "realistic":true, "allow_privileged":false, "autostart":false }
GET  /v1/health → 心跳 + 版本
```
- **`based_on_seq` 语义**：若世界在请求执行前已发生显著变化，体侧可拒绝并要求脑用新快照重算（防陈旧计划）。
- **幂等与超时**：每个请求带 `id`；超时后脑必须重新观测再决策，禁止盲目重发。

## 8. 分阶段路线图与验收标准

### P2 · 跑通基本操作（可判定验收）
1. 游戏经 SMAPI 启动、加载专用测试存档后，脑能拿到真值快照（含农场摘要），单次 `observe` 延迟 **< 200 ms**。
2. `move_to`：农场内随机 10 个目标点，成功率 **≥ 9/10**，单次超时 < 8 s。
3. **`FarmHouse → Farm` 指定格自动走出，成功率 ≥ 9/10**（旧方案的死结，必须首先证明它被解开）。
4. `till / water / plant / clear_debris` 各 10 次，**后置校验通过率 100%**（不允许"报了成功但世界没变"）。
5. 断线/超时/模态干扰下不进入无限重试；每次失败都有可读原因并落到经验库。
6. 全过程 trace 落盘并能离线回放。

### P3 · 农场清理 + 规划种田（端到端，无人介入）
1. 给定目标："清理 A 区域障碍 → 开垦 N 格 → 种下防风草 → 浇水"，**全自主完成**，且由游戏状态判定（地块数、作物数、已浇水数、背包变化）。
2. 自主处理体力不足（进食/回家睡觉）与时间耗尽（睡觉），**连续 3 个游戏日无人工介入**。
3. 失败经验进入记忆，跨日对比同类失败率**下降**（证明"会学习"，而不是重复踩坑）。
4. 产出可读的每日日报（做了什么、为什么、卡在哪）。

### P4+ · 能力扩展（不在本阶段承诺）
温室解锁、社区中心、采矿、钓鱼、畜牧加工、NPC 关系、自动买卖与装备升级、崩溃自愈重启。

### 统一指标口径（每个阶段都必须报，避免"感觉变好了"）
`SR（成功率）` / `预算受限 SR` / `token per task` / `每步延迟` / **`Recovery-Stuck Ratio`（卡住-恢复比）** / `每游戏日人工介入次数`（P3 目标为 0）。
任务定义一律用 YAML 套件（§9），以便与 StarDojo/SPIKE 的公开结果同口径对比。

   ```yaml
     init_commands: null           # 前置准备（给物品等）
     evaluator: clear              # clear/till/sow/water/harvest —— 用观测差分判定
     difficulty: easy              # 步数预算 30/50/150
   ```
   判定一律走**前后观测差分**（`count_check` 风格），**不接受 LLM 自评**。
6. **存档基线**：测试存档记录 SHA-256；每次运行前快照；卸载/安装 mod 前先备份（`SaveBackup` 已在）。**绝不用真实存档做破坏性测试。**

| **🔴 Steam 云同步悄悄覆盖测试存档** | 不可逆、且**不易察觉** | 实测（2026-10-11）：本机 Stardew 的云同步**是开着的**（`localconfig.vdf` → `"cloud":{"last_sync_state":"synchronized"}`），`remotecache.vdf` 里列着 `Wahaha_450799035` 全部存档文件的同步记录，且在我们那次真机测试**退出时自动同步过**。<br>危害：① 测试弄乱存档会同步上云；② 本地损坏时 Steam 可能用云端旧版"修复"，让 `save-backups/` 失去意义；③ 换机/重装时云端会覆盖测试基线。<br>**对策：关闭该游戏的 Steam 云同步**（库→右键→属性→通用→取消"将游戏存档保存到 Steam 云"），让本地快照成为唯一权威备份。<br>另：游戏启动**不依赖 Steam**（无 Steam DRM，靠 `steam_appid.txt`），但成就/时长/覆盖层/云同步依赖它。 |
| 换日/睡觉死锁（无人值守最经典的死锁点） | 整夜停摆 | 快脑负责"日终/2:00 自动上床"，把 sleep 当作一等公民的模态流程处理，而不是等看门狗 |
| 卡住无法自恢复 | 静默停摆 | 进度不变量（N 分钟内必须发生 位置/资源/任务 之一的变化）+ 升级阶梯 + Recovery/Stuck Ratio 指标 |
| 静默动作失败（如背包满导致掉落） | 账实不符 | 回执与账本分离；一切以后置观测差分为准；`needs_review` 不允许冒充完成 |
| 决策/动作频次不匹配、tick 频率错设 | 状态错乱 | 体侧动作全部在 `UpdateTicked` 上推进；频次写进配置并纳入验收 |
| 渲染停滞 / 窗口失焦 | 主线程动作超时 | 关掉"失焦暂停"（旧方案已实测确认游戏会读该选项）；心跳异常即判定卡死并停止自动化 |
| 单组件崩溃拖垮全局 | 全局停摆 | 脑与体隔离（体崩了脑能感知并等待/重启）；模块级隔离；崩溃后**保留证据、不自动盲目续跑**（核对存档身份/位置/背包后再决定） |
| LLM 幻觉产出不可行计划 | 空转 | schema + 字段存在性 + affordance 前置校验 + 降级到效用层继续玩 |
| LLM 成本失控 | 花钱 | 事件触发摊薄（§5.5）+ 日调用上限 + 简报硬预算（≤2 KB）+ 处境缓存；对标值：全成就 153 小时 ≈ ¥213 |
| 陈旧计划覆盖新世界 | 行为错乱 | `world_seq` + `based_on_seq` 拒绝机制 |
| 盲目堆记忆反而变差 | 动作级失败增加 | 记忆三分 + 上下文投影 + **在动作层做约束**（不靠"喂更多状态"解决 SKIP） |
| 反作弊/ToS | 封号风险 | 单机离线自用、仅本机 mod、不涉多人联机；不改游戏本体与存档二进制。**EULA 原文未确认，不对外做合规声明** |
| 多人 co-op 场景 | 影响他人 | 自动化只用于单人存档；不冒充 farmhand 进入他人世界 |
