## P0-1（→ task-218、task-222）：`farm.blockers` 在观测里不存在，护栏 B 必须改逐格判据

**事实**：`mod/AgentFarm.Bridge/Contracts.cs:751-796` 的 `FarmView` 只有
`loaded/hoeDirt/emptyDirt/crops/ripeCrops/readyCrops/deadCrops/unwateredCrops/dryCrops`
——**没有 `blockers`，也没有 weeds/stones/twigs/trees/clumps 计数**。`brain/agentfarm/planner.py:1512` 的 `blockers` 是 summary 回退分支的**简报侧合成值**，且 `farm.get("trees")` 恒取不到 ⇒ 原计划"`clear_area` 有 ok 步但 `farm.blockers` 未降 ⇒ 判红"**按字面不可实现**。

**改法（护栏 B）**：
- 主判据改**逐格/逐 kind**：`clear_area` 阶段里每个 ok 步必须能给出 `cleared_tiles` 或 kind 状态变化（`tree→stump` 记 **progress，不算红**；`weed/stone/twig` 消失 = 真 progress）；`clear()` 返回的 `StepResult.after` 必须带**该格的 before/after kind**。
- farm 级聚合（若 task-222 加了计数）**只作 info**，不进判红条件；不许把"窗口切片"与"全场聚合"混算。
- 顺手修：`tree`/`fruitTree`/`clump` 都映到 `counts["trees"]` ⇒ summary 下失真；拆成独立 kind 计数。

**改法（task-222 追加，纯加法）**：`FarmView` 增加 `weeds/stones/twigs/trees/clumps`（`clumps` 再分 stump/log/boulder/rockPile 更好）计数，与现有 `farm.complete` 同一次扫描同源；缺字段 ⇒ 三态可辨。此项是"农场级障碍趋势"的正规来源，也是目标 1「整场清完」的**验收计数基础**。

## P0-2（→ task-218）：护栏 A 必须端到端，不能只测 `clear()` 单点

**事实**：会"丢 kind"的层至少 6 处：`SKIP_KINDS`、`clear()`、`_stage_tiles`、`_plot_has_work`、`_plot_brief`、`_apply_policy`；只测 `clear()` 会被"换壳静默跳过"绕过。且 `DEFERRED_KINDS` 现在**谁都能加一类**就永久绿 —— 正是当初 `SKIP_KINDS` 事故的重演。

**必修**：
1. **端到端矩阵**：对 `OBSTACLE_KINDS ∪ CLUMP_KINDS` 每一类，从"合成观测喂 planner → `_plot_brief` → `_stage_tiles` → `clear()`"整链跑一遍，断言"要么产出可执行目标，要么登记 deferred 且简报如实出现'暂不支持'字样"。
2. **一致性约束**：`SKIP_KINDS ⊆ DEFERRED_KINDS`（代码断言 + 单测）。
3. **白名单快照**：`DEFERRED_KINDS` 的键集合快照测试，**当前只许 `{fruitTree, bush}`**；新增必须显式改快照 + 在卡/文档说明能力缺口与修复计划。
4. **注册表漂移测试**（照 `TestEventMappingDrift` 的先例）：新增 kind 而不动测试 ⇒ 红。
5. **fail-closed announce**：`tiles` 缺失/截断时，`DEFERRED_KINDS` 也必须被简报公告（现在靠 `present_kinds`，summary 快照下简报可能零字提及 ⇒ 模型永远不知道）。

## P0-3（→ task-219、task-220）：原因码与单位对账（判据 §8 修订）

1. **拆 `cancelled_by_verify`**：`intent_verdict` = cancel ⇒ `no_target`；= unknown ⇒ 新码 **`unknown_evidence`**；策略层改写顺序/合并（`_apply_policy`）⇒ 新码 **`superseded`**。三者不得混用。
2. **补全"半途真实失败"码**（完备映射表 + 漂移测试）：`tool_ineffective`、`sow_failed`、`no_seed`、中途 `stamina` 耗尽、`no_slot`、`blocked_modal`、`world_stuck` 必须各自映射到确定原因码；映射表落地在 `brain/agentfarm/`（单一数据源）+ `tests/` 漂移测试。
3. **`no_target` 证据 schema**：必须带 `evidence`（`stage_tiles_empty: true` + 当时的窗口/农场计数快照 id 或 `obs_seq`）；`tiles` 缺失/截断/证据不可用时**禁止裸用 `no_target`**（应落 `unknown_evidence`）。
4. **跨日归属与唯一性**：`intent_id` 全局唯一（建议 `<day_key>#<seq>`）；跨日续跑的意图在**新一天**重开一条新 id（旧 id 记 `carried_over: true`），`intent_execution` 记在"该 id 被换掉/收尾的那一天"的 `day_end`。
5. **单位与不变式（瓦片制）**：`requested_tiles = ok_tiles + failed_tiles + unexecuted_tiles`；`Σreasons.count = failed_tiles + unexecuted_tiles`。`reasons.count` 明确按**瓦片数**计，不按 step 数。
6. **ACTIONLESS 白名单**：`sleep` / `review` / `wait_for_save` / `recover_stamina` 这类无动作意图在 `_verify_intents`（`longrun.py:5924-5926`）不产生 verdict ⇒ 必须有 `ACTIONLESS_TASKS` 白名单，否则 §8.3.2「executed_steps==0 且无原因码」会天天误报。

## P0-4（→ task-220、task-222）：gaps 跨 run 分层

- brain 只写 **per-run** `<journal>-gaps.json`（保持 run 隔离，A″/B″ 对照不被污染）；
- **跨 run 长期缺口**由 analyzer/工具侧只读聚合到 `logs/gaps-registry.json`（按 `(kind, tool, reason)` 聚合 count/first_seen/last_seen；**只读、不进 checks、不进 rc**）；
- gaps 文件：schema 头 + 原子写（tmp+replace）+ 坏文件归档（`.bad.<ts>`）+ **写失败记 problem**（缺失 ≠ 通过）；
- **gaps 禁止自动转 lessons**（会污染 L0–L5 证据链；转换必须人工/Lead 卡）。
