# 04 · 配置与密钥

> 本文记录的每一项都是**实测过的**，不是"应该如此"。改动配置前先读这里。

---

## 1. 密钥存放

| 项 | 约定 |
|---|---|
| 目录 | `<仓库>/secrets/` |
| DeepSeek 密钥 | `secrets/deepseek.key`，**单行纯文本**，无引号无前缀 |
| 版本控制 | **绝不入库**。`.gitignore` 已排除 `secrets/`、`*.key`、`.env*` |

代码读取顺序（`brain/agentfarm/llm.py`）：

```
1. 环境变量 DEEPSEEK_API_KEY     ← 优先（便于临时换 key、CI、多环境）
2. <仓库>/secrets/deepseek.key   ← 日常使用
3. 都没有 → LlmError(status="no_api_key")，报错里会写清两个位置
```

> **安全纪律**：密钥只出现在 `llm.py` 的请求头里。**不进日志、不进异常消息、不进 trace**。
> `agentfarm llm-check` 只打印来源、长度与前 6 位前缀用于辨认。

⚠️ 如果密钥曾经贴在聊天记录、截图或公开仓库里，请到 DeepSeek 控制台**轮换**它。

## 2. 环境变量总表

| 变量 | 作用 | 缺省 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 密钥（优先于文件） | 读 `secrets/deepseek.key` |
| `DEEPSEEK_BASE_URL` | API 端点 | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 模型名 | `deepseek-flash` |
| `AGENTFARM_SECRETS_DIR` | 密钥目录（测试用） | `<仓库>/secrets` |
| `AGENTFARM_PYTHON` | 指定 Python 解释器 | 见下节解析顺序 |
| `AGENTFARM_BRIDGE_JSON` | `bridge.json` 位置（测试/多实例） | `%APPDATA%\StardewValley\AgentFarm\bridge.json` |

## 3. 模型选择（2026-10-11 实测）

```
GET https://api.deepseek.com/models  →  deepseek-flash, deepseek-v4-pro
```

用户选定 **`deepseek-flash`**。它是**推理模型**——响应结构：

```json
{ "choices": [ { "message": { "role": "assistant",
                              "content": "最终回答",
                              "reasoning_content": "思考过程" },
                 "finish_reason": "stop" } ],
  "usage": { "prompt_tokens": 77, "completion_tokens": 7046,
             "completion_tokens_details": { "reasoning_tokens": 6977 } } }
```

### 🔴 实测的延迟与开销（这组数字直接影响架构）

| 问题规模 | 延迟 | completion | 其中推理 | 合计 |
|---|---|---|---|---|
| 极短（"压缩成 4 个字"） | **3.2 s** | 499 | 496 | 545 |
| 真实规划（"482 金、体力 268、农场 443 杂草…今天最优先做什么"） | **41.4 s** | 7046 | **6977** | **7123** |

**三条硬结论**

1. **推理 token 占 95% 以上**，成本几乎全在"思考"上 → 慢脑必须**事件触发 + 少调用 + 缓存**（架构 §5.5）。
2. **一次真实规划要 41 秒现实时间 ≈ 游戏内 58 分钟**。也就是说 **LLM 思考时游戏世界在流逝**——这是"低频 LLM + 高频代码"路线必须正面处理的成本。
   → P3 计划采用的合法对策：**思考前用游戏菜单把时间暂停**（单人模式下打开菜单会停时间；这是完全合法的游戏操作，不违反决策 D4"不做特权操作"）。**待 P3 真机验证该行为。**
3. **`max_tokens` 必须给足**（缺省 8192）。踩过的坑：给 2048 时，token 全被思考吃掉，`content` 返回**空字符串**且 `finish_reason=length`——如果客户端只看 `content`，就会把"模型没想完"误判成"模型无话可说"。
   本客户端把它识别成 `LlmError(status="truncated")`，绝不静默放过。

## 4. 失败处理（`LlmError.status`）

| status | 触发条件 | 是否重试 |
|---|---|---|
| `no_api_key` | 两处都找不到密钥 | 否 |
| `unauthorized` | HTTP 401 | 否（重试无意义，直接报） |
| `rate_limited` | HTTP 429 | 是（指数退避，最多 3 次） |
| `server_error` | HTTP 5xx | 是（同上） |
| `network` | 连不上 / 超时 | 是（同上） |
| `truncated` | 内容为空且被 max_tokens 截断 | 否（应调大预算） |
| `bad_response` | 非 200 且非上述，或响应结构异常 | 否 |

不存在的模型名会返回 **HTTP 400** 且报文里列出可用模型（实测）：

```
The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-nonexistent.
```

## 5. Python 解释器解析顺序

本机 PATH 里的裸 `python` 是 **Microsoft Store 占位符**，直接调用会静默失败。`tools/agentfarm.ps1` 按以下顺序挑真实的解释器：

1. `AGENTFARM_PYTHON` 环境变量
2. `brain/.venv/Scripts/python.exe`（项目自带虚拟环境）
3. DSH 自带运行时 `C:\Users\admin\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`（**本机实测可用，含标准库**）
4. WorkBuddy 自带运行时
5. PATH 里的 `python`（**排除 `WindowsApps` 占位符**）

## 6. 三个环境级陷阱（都已修掉，别再踩）

| 陷阱 | 现象 | 处理 |
|---|---|---|
| PowerShell 执行策略禁止 `.ps1` | `running scripts is disabled on this system` | 用 `tools/agentfarm.cmd`（内部 `-ExecutionPolicy Bypass`），不改系统策略 |
| PowerShell 5.1 把无 BOM 的 `.ps1` 当 ANSI 读 | 中文注释让脚本**解析失败**（`Unexpected token`） | 两个可行解，按场景选：① **启动脚本只写 ASCII**（`tools/agentfarm.ps1` 用这种，最稳）；② **写成 UTF-8 带 BOM**（`mod/build.ps1` 用这种，因为它的中文提示需要保留）。无 BOM + 中文 = 必坏 |
| Python stdout 默认 `cp1252` | 一旦重定向/管道，打印中文直接 `UnicodeEncodeError` 崩溃 | 入口 `stream.reconfigure(encoding="utf-8")` + 包装脚本设 `PYTHONUTF8=1` |
