## §4 判据纪律（违反会被评审打回）

1. **判据只用独立观测差分**：不信回执、不信自述、不信账本单方面说"完成"。`observe?detail=full` 的 `tiles[]`/`farm` 计数 + 存档四件 + SMAPI 原文才是证据。
2. **缺失 ≠ 通过**：字段/文件/事件缺失一律写【无法判定】。
3. **骨架/探针自己的 bug 与产品 bug 分开判**：探针误判改判据，不许改结论（例：`scratch/smoke-0742.py:377` 曾硬编码 `EXPECT_VERSION=0.7.42`，属探针缺陷）。
4. **变异必须报实测杀数**：作者自报杀数不算，必须在 `git archive <冻结提交>` 的冻结副本上复跑（**禁止原地变异**，CRLF 会被写坏；锚点会随版本失效，如 task-35 的 t15 变异在后续树上 0 命中）。
5. **不许为变绿放宽判据**：`unreachable_within_bound` 与 `bound=max(5,20%)`、`no_unmet_stages`、护栏 B、checks 10 键语义，都不能为了让某天 VERIFIED 而改。
6. **数值安全**：禁止直写钱/物品/容量（`money+=`、`Game1.player.Money=`、`Items`、`MaxItems`、`increaseBackpackSize` 一律禁止）；一切经济动作走游戏入口（`ShopMenu.tryToPurchaseItem`、`Farm.shipItem`、`sell`），并用观测差分验证；卖东西走白名单+保留量。
7. **游戏开着必须有脑在跑**：跑完立刻 `stop-game`。历史事故：老会话脑死 + 子代理一起死 ⇒ 游戏无人看护跑了 1h43m、多落盘 7 天、证据全废；另有 3 次 2:00 强制昏睡各扣 10% 金币。

### 5.2 任务板与消息机制

- 任务板是唯一排期真相：`team_task_list` → `team_task_get`（拿 latest revision）→ `team_task_update(action=claim, expected_revision=<latest>)` → 干活 → `complete`。**revision 过期会报 stale，重 get 再试。**
- 队友是惰性的：`list_agents` 看状态；`inactive` 只是没在跑，**必须 `send_message` 才会唤醒**。发消息要自包含（任务 id、commit、sha、命令、判据、纪律），不要假设它有你的上下文。
- 长跑期间 Lead 用 `wait_agent` 等，不要忙轮询；收工后用 `job_output`/`list_agents` 复核。
- 你是 Lead：**验收必须自己抽验**（`git log/show/status`、亲自跑定向单测），不要直接采信队友报告里的读数。历史上有 NIT-6 类"自报 1330 vs 冻结树 1324 差 6【无法判定】"，就是靠抽验发现的。

### 5.3 Git 纪律（血泪教训）

- **禁 `git commit --amend`**（曾改写历史、顶掉别人的提交 `bb40a55`）。
- **禁 `git add -A` / `git add .`**：只按路径 add；提交前 `git diff --cached --name-only` 逐条核对；提交后 `git show --stat HEAD` 自检。
- 提交信息格式：`类型(范围): 一句话`，如 `fix(longrun): 收尾关掉推迟保存的模态`。
- 工作树里别人的在制改动**不许**顺手提交或回滚。
- `check-release` 的"工作树干净"项会因为**别人未跟踪的 scratch 文件**变红——正确做法是让对方按路径提交自己的文件，不是 `git add` 别人的东西。

## §8 踩坑清单（省你几小时）

- **`bin\Release` 污染事故**：`deploy-mod.py` 无条件复制该目录 dll；WIP 构建曾把 291,840B 的 dll 当冻结产物。⇒ 冻结时在冻结提交上 `dotnet build --no-incremental` 重建，再核 dll SHA256 与冻结产物一致才 deploy；`deploy-mod.py` 前先记 dll 哈希。
- **check-release"工作树红"**：多半是别人未跟踪的 `scratch/*.py`；让作者按路径提交，别替人 add。
- **`scratch/_ledger_*.jsonl` 夹具不在仓里**：纯 `git archive` 冻结树全量单测会少 4 个夹具而红；deputy 验收时会把夹具拷进临时树，读数差额（如 1383 vs 1377）要如实写【无法判定】，并在冻结树补夹具后复跑。
- **XNB 离线解压失败**（`Content/Data/Shops.xnb` 非标准 LZ4/deflate）：别再手写解压器，用真机探针取数据（已用只读 `buy` 探针拿到货架 20 条）。
- **Probe 探针要只读**：`buy` 探针传不存在的 item 名只会得到 `item_not_sold` 回执（顺带拿到完整货架）；`talk` 探针永不应答 `Purchase`。
- **事件卡死会连环重启**：task-34 探针因 Town 事件卡死反复起游戏 6 次，用户会看到"连续启动几次都没进行下去"；正确做法是当次跑完即停、把时间线写进证据，不要自动重试到天亮。
- **`analyze-longrun` CLI**：用 `--journal <path>`，不能传位置参数；`analyze` 的 rc 会被 `slot_relief` 等字段缺失带红（就是现在步 7 的问题）。
- **pwsh 退出码**：`unittest` 的 stderr 输出会让 `[exit code: 1]` 假红；`dotnet` 的 CRLF warning 无害。
- **变异脚本锚点会过期**：旧版本的变异脚本在新冻结树上可能 0 命中（RC=2 中止），必须重新定位锚点或写新变异，报告里如实写"不可复现"。
