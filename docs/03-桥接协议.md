# 03 · 桥接协议 v3（Mod ↔ 脑）

> **状态**：`draft-3`（2026-10-11，修复迭代 3：真机“冻结”事故修复）
> **定位**：这是**唯一的契约来源**。C# 侧与 Python 侧都必须按本文实现；字段名逐字一致。
> **教训来源**：旧方案（`_legacy-audit.md` §5 缺陷 D5）"schema 声明了却从不校验、C# 写 `/1` 而 Python 写 `/2`、白名单两份硬编码"。本协议要求两侧**都做版本校验**，不匹配必须报错而不是静默继续。

---

## 1. 传输层

| 项 | 约定 |
|---|---|
| 监听 | `127.0.0.1`，仅本机 |
| 端口 | 首选 `17890`，占用则依次 `17891..17900`，再失败用系统分配的空闲端口 |
| 协议 | 手写极简 HTTP/1.1（`TcpListener`）。**不用 `HttpListener`**——它对 URL 前缀有 ACL/管理员要求，会给无人值守部署带来不确定性 |
| 编码 | 请求与响应正文均为 UTF-8 JSON |
| 响应头 | `Content-Type: application/json; charset=utf-8`、`Content-Length`、`Connection: close` |
| 鉴权 | 除 `GET /v1/health` 外，所有请求必须带 `X-Auth-Token: <token>` |

**线程纪律（不可违反）**：网络线程**绝不**直接访问任何游戏对象。所有需要读游戏状态的请求入队，由 `UpdateTicked`（主线程）排空执行，结果经 `TaskCompletionSource` 交回网络线程。每次 tick 最多处理 1~2 个请求。

## 2. 服务发现

Mod 启动后写 `%APPDATA%\StardewValley\AgentFarm\bridge.json`（原子写：先写临时文件再 `File.Move` 覆盖），退出时删除。

```json
{
  "schema": "agentfarm-bridge/1",
  "port": 17890,
  "token": "3f2a…（32 位随机十六进制）",
  "pid": 12345,
  "modVersion": "0.2.0",
  "gameVersion": "1.6.15",
  "smapiVersion": "4.5.2",
  "startedAt": "2026-10-11T17:00:00+07:00"
}
```

`modVersion` **必须来自 `manifest.json`**（C# 侧取 `ModManifest.Version`，构造 `BridgeHost` 时传入），不得在代码里写死常量：写死会让日志 / `bridge.json` / `/v1/health` 三处与 manifest 悄悄脱节（v2 真机上就出现过 manifest=`0.2.0` 而三处都报 `0.1.0`）。

## 3. 错误约定（所有接口通用）

除成功外，`ok` 恒为 `false`，且**必须**给出中文 `reason`：

```json
{"ok": false, "status": "unauthorized", "reason": "令牌不匹配"}
```

| status | 含义 |
|---|---|
| `ok` | 成功 |
| `no_save` | 尚未加载存档（标题界面） |
| `unauthorized` | 令牌缺失或不匹配（HTTP 401） |
| `not_found` | 路径不存在（HTTP 404） |
| `not_implemented` | 该技能尚未实现 |
| `unknown_skill` | 技能名未知 |
| `precondition_failed` | 前置条件不满足（含"目标不在当前地点"） |
| `unreachable` | 寻路无法到达 |
| `blocked` | 被物体/碰撞阻挡 |
| `timeout` | 超时 |
| `stale` | 决策依据的世界已过期（`based_on_seq` 过旧） |
| `ui_modal` | 被菜单/对话/过场挡住 |
| `world_stuck` | **模态已关闭，但世界没有恢复**（`player.canMove=false` 或 `Context.IsPlayerFree=false`）。见 §6 的 `worldResumed`；脑收到它**必须升级处理（重启游戏）**，不得当作普通成功 |
| `busy` | 已有 exec 在执行 |
| `error` | 内部异常（附摘要） |

### 全局约定：`null` 字段会被省略

C# 侧统一使用 `JsonIgnoreCondition.WhenWritingNull`（`Contracts.cs` 的 `JsonDefaults.Options`）：

- 值为 `null` 的字段**不会出现在 JSON 里**（例如没有菜单时 `ui.activeMenuText` 直接缺失）；
- `false` / `0` / `""` / `[]` **不会**被省略，一定会出现。

**Python 侧必须按"字段可能缺失"解析**（`data.get("activeMenuText")`），**禁止**用 `data["activeMenuText"]` 直接下标 —— 否则会在正常工况下抛 `KeyError`。

## 4. `GET /v1/health`

无需令牌。用于脑的存活探测与版本校验。

```json
{
  "ok": true, "status": "ok", "schema": "agentfarm-bridge/1", "modVersion": "0.2.0",
  "game": { "version": "1.6.15", "smapi": "4.5.2", "windowActive": true },
  "runtime": { "ticks": 123, "uptimeSeconds": 12.3, "worldSeq": 4,
               "hasSaveLoaded": true, "onTitleScreen": false },
  "server": { "port": 17890, "requestsServed": 7 }
}
```

- `game.windowActive` = `Game1.game1.IsActive`。**失焦诊断的关键字段**：真机实测游戏失焦时世界时钟照常推进，但 `PathFindController` 不驱动角色（失焦 10/10 失败，切回前台 5/5 成功）。它有 `false` 时，"角色不动"就不是寻路的错。

## 5. `GET /v1/observe?detail=summary|full`

未加载存档时：`{"ok":true,"status":"no_save","schema":"agentfarm-world/3","hasSaveLoaded":false}`，其余段为 `null`（即**字段缺失**）。

```json
{
  "ok": true, "status": "ok", "schema": "agentfarm-world/3",
  "worldSeq": 42, "generatedAt": "2026-10-11T17:00:00+07:00", "hasSaveLoaded": true,
  "clock":  { "year": 1, "season": "spring", "day": 3, "timeOfDay": 1230,
              "weather": "rain", "weatherOnFarm": "rain" },
  "player": { "name": "Jay", "location": "FarmHouse", "tile": [2, 11], "facing": 0,
              "stamina": 268.0, "maxStamina": 270.0, "health": 100, "maxHealth": 100,
              "money": 482, "farmingLevel": 0, "inventoryCount": 12,
              "canMove": true, "hasController": false, "isInBed": false,
              "tools": { "hoe": true, "axe": true, "pickaxe": true,
                         "wateringCan": true, "fishingRod": false, "weapon": true } },
  "location": { "name": "FarmHouse", "isFarm": true, "isOutdoorFarm": false,
                "isFarmhouse": true, "isOutdoors": false,
                "objects": 1, "debris": 0, "terrainFeatures": 1, "characters": 0 },
  "farm": { "loaded": true, "hoeDirt": 0, "emptyDirt": 0, "crops": 0, "ripeCrops": 0,
            "unwateredCrops": 0, "weeds": 443, "stones": 241, "twigs": 114, "trees": 148,
            "grass": 458, "sprinklers": 0, "machinesTotal": 0, "machinesReady": 0, "animals": 0,
            "complete": true, "scanSeq": 42 },
  "ui": { "activeMenu": "DialogueBox", "isModal": true, "eventUp": false,
          "onScreenMenus": 4, "activeMenuText": "go to sleep for the night?",
          "dialogueResponses": ["Yes", "No"], "dialogueIsQuestion": true },
  "liveness": { "worldAdvancing": true, "secondsSinceClockMoved": 7.3 },
  "game": { "paused": false, "shouldTimePass": true }
}
```

**语义要点**

- `worldSeq`：单调递增。状态指纹（地点名 + 玩家坐标 + 游戏内分钟 + 金钱 + 背包数）变化时 +1。
- `liveness.worldAdvancing`：游戏内时钟在最近 N 秒内推进过。**无人值守的命脉**——它把"世界冻结"与"程序卡住"区分开（旧方案正是分不清这两件事而空转 40 分钟）。
- `detail=summary` **不得**包含全量地块；`detail=full` 可含 `farm.tiles`。
- 农场统计必须能承受 1400+ 格且**不能每帧全量扫描**。
- `clock.weather`：**恒为明确取值**之一 `rain` / `snow` / `lightning` / `debris` / `sunny`，不再返回空串。判定顺序即优先级（雷雨同时满足 IsRainingHere，故 lightning 必须排在 rain 前）。`clock.weatherOnFarm` 用同样的口径读 `Game1.getFarm()`，人在别处也能知道农场天气。
- `location.isFarm` **语义陷阱**：这是 SMAPI 的 `GameLocation.IsFarm`，对 `Farm` **和** `FarmHouse` 都返回 `true`（上面示例里 FarmHouse 就是 `isFarm=true`）。**不能**用它判断"是否站在露天农场上"；那个语义请用 `location.isOutdoorFarm`（= 地点名恰好为 `"Farm"`）。
- `ui.onScreenMenus`：`Game1.onScreenMenus.Count`。⚠️ **它是常驻 HUD**（时钟/体力/金钱/任务提示），实测恒为 4，**与"对话框"无关**。v1 的 `dialogsOnScreen` 名字误导过"脑"，v2 已删除该字段并改名。
- `ui.activeMenuText`：模态里能读到的文字。`DialogueBox` 打开时是 `getCurrentString()`（例 `"go to sleep for the night?"`），其它菜单是类名（例 `"GameMenu"`），没有菜单时字段缺失（null）。
- `ui.dialogueResponses`：`string[]`，对话框各选项的 `responseText`；没有对话框时为 `[]`。
- `ui.dialogueIsQuestion`：当前对话框是否为提问。**这两个字段是无人值守的必需品**：角色走到床边会弹出睡觉确认框并**冻结整个世界时间**，v1 只能给出类名 `"DialogueBox"`，脑无法决定该关还是该答。
- `player.canMove` / `player.hasController`：分别读 `Game1.player.CanMove` 与 `Game1.player.controller != null`，用于把"角色不动"归因清楚（失焦 / 被控制器占住 / 被模态挡住）。
- `player.isInBed`：读 `Game1.player.isInBed.Value`。**v3 新增**。睡觉流程会把人置为 `isInBed` 且 `CanMove=false`、时间冻结，靠它才能区分"正在睡觉/过场流程中"与"被模态挡住"。
- `game.paused`（`Game1.paused`）与 `game.shouldTimePass`（`Game1.shouldTimePass()`，无参重载）：**v3 新增，专治"看起来正常其实停摆"**。**IL 实证**：`shouldTimePass` 内含 `if (!player.CanMove && !player.UsingTool) return player.forceTimePass;` —— 也就是说 **`canMove=false` 本身就会让时间停止推进**。判读口径：
  - `paused=true` → 游戏被显式暂停（菜单/失焦暂停等）；
  - `paused=false` 且 `shouldTimePass=false` → 世界因为别的原因停摆，**先看 `player.canMove`**（这正是本轮"时钟停在 640 + 角色不能动"的组合）；
  - `player.isInBed=true` → 处在睡觉流程里。
  这三个字段是"冻结"事故的定位依据：v2 快照里没有任何字段能说明游戏自己怎么看时间，只能靠猜。

### v2 → v3 字段变更一览

| 段 | 新增 | 删除 |
|---|---|---|
| `player` | `isInBed` | — |
| `game`（新段） | `paused`、`shouldTimePass` | — |
| `exec` | `worldResumed` | — |

### v1 → v2 字段变更一览

| 段 | 新增 | 删除 |
|---|---|---|
| `clock` | `weatherOnFarm` | — |
| `player` | `canMove`、`hasController` | — |
| `location` | `isOutdoorFarm` | — |
| `ui` | `onScreenMenus`、`activeMenuText`、`dialogueResponses`、`dialogueIsQuestion` | `dialogsOnScreen` |
| `game`（health 的 `game` 段，**不是**快照 v3 新加的 `game` 段） | `windowActive` | — |

## 6. `POST /v1/exec`

```json
{ "skill": "move_to", "args": { "tile": [64, 15] }, "timeout_ms": 8000, "based_on_seq": 42 }
```

```json
{ "ok": true, "status": "ok", "skill": "move_to", "reason": "",
  "elapsedMs": 3210, "worldSeqBefore": 42, "worldSeqAfter": 57,
  "uiOpened": true, "activeMenuText": "go to sleep for the night?" }
```

```json
{ "ok": false, "status": "world_stuck", "skill": "dismiss_modal",
  "reason": "已关闭对话框（选“No”：answerDialogue(\"No\")；closeDialogue() 关闭（复位 dialogueUp 与 player.CanMove））：“go to sleep for the night?”；警告：模态已关闭（或本就没有模态），但游戏仍处于不可控状态（canMove=false，isPlayerFree=false），世界没有恢复（CanMove=false 会让 shouldTimePass=false，时钟随之停止推进），需要外部恢复（建议重启游戏）",
  "schema": "agentfarm-exec/2", "worldResumed": false, "elapsedMs": 0 }
```

- `timeout_ms` 夹到 `[500, 30000]`，缺省 `8000`。
- 一次只允许一个 exec 在跑；否则 `busy`。
- `based_on_seq` 过旧时可返回 `stale`（阈值由实现定，写进注释）；脑收到 `stale` **必须重新观测后重算，禁止盲目重发**。
- `uiOpened`（bool，默认 `false`）/ `activeMenuText`（string，仅 `uiOpened=true` 时出现）：**动作成功后是否顺手弹出了模态**。真机场景：`move_to` 到床边会「成功到达」但同时触发 `go to sleep for the night?` 对话框，整个世界时间随之冻结；脑看到 `uiOpened=true` 就必须先 `dismiss_modal` 再继续，**不要**把它当成无关紧要的字段。
- `worldResumed`（bool，**dismiss_modal 专用**，默认 `true`，其它技能恒为 `true` 可忽略）：**判据是"世界恢复了"，不是"菜单关了"** —— 同一 tick 内 `player.CanMove == true` **且** `Context.IsPlayerFree == true` 才算 `true`。为 `false` 时响应同时是 `ok=false` + `status="world_stuck"`，`reason` 里会明确警告"世界没有恢复，需要外部恢复（建议重启游戏）"。脑**必须**据此升级处理（重启游戏），**绝不允许**把它当普通成功继续排计划。
- `schema`（string，可选）标识 exec 响应自身的版本（当前 **`agentfarm-exec/2`**，仅 `noop` / `dismiss_modal` 会带；v1 → v2 的变更即新增 `worldResumed`）。

### 已实现的技能

| skill | args | 说明 |
|---|---|---|
| `noop` | 无 | 立即返回 `ok`，**不碰游戏**。用于验证通信链路 |
| `move_to` | `{"tile":[x,y]}` | 用游戏自带 `PathFindController` 走到目标格 |
| `dismiss_modal` | 无 | 关掉当前挡路的模态（**无人值守的救命技能**），单 tick 完成 |

`move_to` 规则：
1. 目标格不在当前地点 → `precondition_failed`（reason：「跨地点移动尚未实现」）。
2. 到达判定 = 玩家当前 tile == 目标。
3. 超时 → `timeout`，并**必须停止寻路**（`Game1.player.controller = null`），不得把玩家卡在控制器里。
4. 有活动菜单/对话/过场 → `ui_modal`。
5. 目标格上有**家具**（床/桌椅等）→ `precondition_failed`，reason 写明「该格有家具（床/家具），不能作为落脚点」。理由：床自带碰撞，A\* 永远进不去，且真机上"到床边"会触发睡觉确认框冻结时间；提前挡住比事后补救便宜。此检查与"不可通行（`unreachable`）"语义不同，独立报告，且**必须先判家具、再判不可通行**（v3 修的死代码 bug：`SafeStandable` 发现家具时返回 `false`，先判 `!standable` 会让家具分支永远不可达）。
6. **家具命中范围用像素包围盒**（v3 修）：`f.GetBoundingBox()` 与目标格像素矩形 `new Rectangle(x*64, y*64, 64, 64)` 相交即算命中。只比 `f.TileLocation == 目标格` **范围太窄**：真机上 `move_to(10,9)` 通过了检查、成功走到该格**并触发了睡觉弹窗**（床的触发区覆盖了 (10,9)，但床的 `TileLocation` 不在这格 —— 床是多格家具）。实现依据（IL 实证）：`Furniture.GetBoundingBox()` 走 `Furniture.GetBoundingBoxAt`，返回家具自己的 `boundingBox.Value`，而它由 `getDefaultBoundingBoxForType` 构造为 `(TileLocation.X*64, TileLocation.Y*64, 宽*64, 高*64)` —— 世界像素坐标、尺寸按格数放大。⚠️ 1.6.15 的 `Furniture` 上**没有** `getBoundingBox()`（CS1061 编译期证伪），可用的是继承自 `Object` 的 `GetBoundingBox()`，且对 Furniture 是**只读**的。
7. 成功到达后若 `Game1.activeClickableMenu != null`，返回里置 `uiOpened=true` 并带上 `activeMenuText`。

`dismiss_modal` 规则（**安全第一，严格遵守**）：

| 情况 | 行为 |
|---|---|
| `DialogueBox` 且是提问（`isQuestion` 且 `responses.Length > 0`） | **永远选"否/取消/关闭"那一项，绝不选 Yes**。判定优先级：`responseKey` 或 `responseText` 命中 `no`/`cancel`/`close`/`never`/`否`/`不`/`取消`（大小写不敏感）→ 选它；找不到明确的"否"时**选最后一项**（星露谷惯例：否/取消在后），并在 `reason` 里注明「按惯例选了最后一项」 |
| 任何 `DialogueBox`（含上一条选完否之后） | **先 `closeDialogue()`**（等价玩家正常结束对话，复位 `Game1.dialogueUp` 与 `Game1.player.CanMove`）；仍在才退回 `exitThisMenu()` |
| 其它任何 `activeClickableMenu != null`（非对话框菜单） | 调 `exitThisMenu()`（等价玩家按 Esc） |
| 没有模态 | 返回 `ok`，`reason` =「当前没有打开的模态」；`worldResumed` 仍按下面的判据如实给出（可用于发现"早就在停摆"） |

**⛔ 禁止按确认键（本轮事故的硬结论，不要"优化"回去）**

- **禁止**用 `receiveKeyPress(Keys.Enter)` / `Keys.Space` / `Keys.Down`（以及 `selectedResponse`）去"选中并确认"某个选项。真机事故：走到床边 → `Go to sleep for the night?` → 旧实现报「已关闭对话框（选“No”（按键确认未生效，已退回 exitThisMenu 关闭））」，**随后游戏永久卡死**：时钟停在 640、`isModal=false`、`canMove=false`、世界 45 秒以上不推进、玩家无法控制角色。
- **IL 实证的完整成因链（1.6.15）**：
  1. `Game1.drawObjectQuestionDialogue` 弹提问框时会 `activeClickableMenu = new DialogueBox(...)`、`dialogueUp = true`、**`player.CanMove = false`**；
  2. `DialogueBox.receiveKeyPress` 在提问时只识别「选项热键 / `'N'`(78) / `'Y'`(89) / `Options.menuButton`」，**Enter(13) 与 Space(32) 在这里没有任何"应答"语义** —— 若该键在 `Options.actionButton` 中，就会被那个分支转成 `receiveLeftClick(0, 0, true)`，也就是"确认当前选中项"，使对话框进入 `transitioning` 中间态（菜单仍在，所以按键路径自己都判断"没关掉"）；这一层（actionButton 默认是否含这两个键）未逐字段核实，但**这条路径整体语义不可控、可能真的确认某个选项**，所以整条删除；
  3. 兜底的 `exitThisMenu()` 把菜单抽走，而 `DialogueBox.cleanupBeforeExit()` 是**空方法**：`exitThisMenu()` **不复位 `Game1.dialogueUp`，也不复位 `player.CanMove`**；
  4. `Game1.shouldTimePass()`：`if (!player.CanMove && !player.UsingTool) return player.forceTimePass;` → `CanMove` 停在 `false` ⇒ **时间永远不再推进**。
  结论：这不需要"真的按了 Yes"就会发生，**根因是关闭路径选错了 API**；而按键路径在语义上不可控（可能真的确认某个选项），必须整条删除。
 - 提问的**应答**优先走 **`Game1.currentLocation.answerDialogue(chosen)`**（`chosen` 就是 `box.responses[i]` 本身）。
  **为什么优先它而不是 `answerDialogueAction`**：`answerDialogue(Response)` 才是**游戏自己**的入口 —— 它内部把答案拼成 `lastQuestionKey 第一段 + "_" + responseKey`（例 `"Sleep_No"`）再转调 `answerDialogueAction`，并且**会消费 `location.afterQuestion`**，也就是执行"回答之后本应发生的事"（例如把角色从床上移下来）。**直接调 `answerDialogueAction` 会跳过这段副作用**，留下"答是答了、状态没走完"的半成品。
  仅在 `answerDialogue` 抛异常时才退回 `answerDialogueAction(组合键)`；`lastQuestionKey` 为空则退回裸 `responseKey`（再为空退回 `responseText`）。注意**裸传 `"No"` 在所有 `questionKey_xxx` 型对话框上都是空操作**，所以拼法必须与游戏一致。
- 返回的 `reason` **必须写清关掉的是什么、怎么关的**，例：`已关闭对话框（选“No”：answerDialogue("No")；closeDialogue() 关闭（复位 dialogueUp 与 player.CanMove)）：“go to sleep for the night?”`。
- 关闭后**必须复核世界是否恢复**（`player.CanMove` 且 `Context.IsPlayerFree`），不满足就是 `ok=false` + `status=world_stuck` + `worldResumed=false` + 明确警告：**"关掉菜单"不等于"世界恢复"**。
- 唯一允准的状态写入：`Game1.dialogueUp = false`（`ModalDismiss.ClearDialogueFlag()`），且只在 `closeDialogue()` 之外的兜底路径或菜单已消失而标志残留时调用。它是全项目唯一一处直接写游戏状态，架构文档 §2 原则 7 的豁免清单有记录；**不得新增**别的状态写入。
- 合法性：以上全部等价于玩家点击"否"选项或按 Esc 结束对话，不涉及任何特权操作。

## 8. 版本校验（强制）

- C# 侧：`GET /v1/observe` 响应必须带 `schema: agentfarm-world/3`；`POST /v1/exec` 中 `dismiss_modal` / `noop` 的 `schema` 为 **`agentfarm-exec/2`**（新增 `worldResumed`）。
- Mod 版本号（`bridge.json` / `health.modVersion` / 启动日志）唯一来源是 `manifest.json` 的 `Version`；当前 `0.2.0`，**不得在代码里写死**。
- Python 侧：`doctor` 命令必须校验 `schema`、`game.version`、`smapi` 与预期基线（1.6.15 / 4.5.2）一致，**不一致要显著告警而不是静默继续**。
- 任何一侧改字段，必须同步改本文并 +1 schema 版本号。
- ⚠️ **`null` 字段会被省略**（见 §3 全局约定）：Python 侧解析一律用"字段可能缺失"的写法。
